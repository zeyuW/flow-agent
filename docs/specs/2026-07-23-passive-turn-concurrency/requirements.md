# 被动回合并发与会话隔离：需求文档

- 状态：已验证
- 创建日期：2026-07-23

## 背景

主循环为每个入站消息创建协程任务，但该任务直接调用同步的被动回合管道。模型调用、工具调用和出站准备会阻塞事件循环，因此不同会话无法获得真实并发。

同时，Agent 使用可变的 session_id 保存当前会话。若未来仅通过线程池并发执行同步管道，多个回合可能覆盖该状态，造成历史读取、提示词构建或提交回合串线。

## 目标

- 不同会话的慢速被动回合可并发推进，不阻塞事件循环消费其他会话。
- 同一会话仍保持严格 FIFO，一次只能执行一个被动回合。
- 会话身份必须显式传递，不依赖共享的可变当前会话状态。
- 取消和停止必须安全收束，不允许已取消的包装协程遗留不可控的后台执行。

## 范围

- 包含：被动主循环、被动回合管道、Agent 会话访问和模型调用接口的异步边界。
- 包含：同会话 FIFO、跨会话并发、会话隔离与取消语义测试。
- 不包含：主动回复、空闲任务、后台作业和渠道协议重构。

## 约束

- 保持现有同步入口 run_once 的兼容行为，或提供明确的兼容适配层。
- 不通过 asyncio.to_thread 包裹整个回合实现表面并发；该方式不能可靠取消底层工作，且会放大共享状态竞争。
- 不改变现有会话数据格式和已持久化记录。
- 新增或修改的注释、文档字符串使用中文。

## 验收标准

- [ ] 一个会话被模型调用阻塞时，另一会话仍能开始并完成其回合。
- [ ] 同一会话的第二条消息只能在第一条回合终态后开始。
- [ ] 两个并发会话的提示词历史和最终提交不相互混入。
- [ ] 取消或停止时，不会留下未受控的模型、工具或回合任务。
- [ ] 相关单元、集成和回归测试通过。
