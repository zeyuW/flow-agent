# 插件候选原子发布：需求文档

- 状态：已批准
- 创建日期：2026-07-27

## 背景

当前插件管理器在一轮热重载中按发现顺序逐个发布候选插件。后面的候选若无效，前面的插件已经更新，用户得到一轮半更新的运行时状态。

## 目标

一轮热重载必须先准备全部变化插件；仅当所有候选均有效时，才开始发布本轮更新。候选失败时完整保留当前已发布插件。

## 范围

- 包含：
  - 一轮协调内全部变化插件的候选准备。
  - 候选初始化或声明校验失败时的候选资源清理。
  - 所有候选准备成功后再按既有绑定机制发布，并继续触发现有 MCP 与主动链路刷新。
- 不包含：
  - 快照、lease、旧代延迟回收或三条链路入口改造。
  - 改变消息协议、主动准入、ACK、调度或后台重试语义。

## 约束

- 兼容性：未注册插件时，现有核心能力必须继续工作；已有 Plugin 接口不要求修改。
- 生命周期：候选准备失败不得停止或修改当前插件；已准备但未发布的候选必须关闭并卸载模块。
- 资源：继续使用既有发布、MCP 和主动刷新机制，不新增持久化协议。

## 验收标准

- [x] 同轮中任一候选损坏时，其他候选不会发布，当前工具与后台 Job 保持旧值。
- [x] 已准备但未发布的候选在失败路径释放实例与导入模块。
- [x] 所有候选有效时，既有插件更新、移除和贡献刷新回归保持通过。
- [ ] `bash scripts/verify.sh` 全量通过。
