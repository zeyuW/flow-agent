# 扩展 API 文档设计说明

## 1. 目标

新增 `docs/api.md`，为二次开发者提供一个单一、可直接阅读的扩展入口，说明如何通过 Plugin、MCP 和 Skill 三条路径为 Flow Agent 增加能力。

文档不只是列出源码接口，而是先帮助开发者选择正确的扩展方式，再给出最小目录、配置、生命周期、安全边界和验证方法。

## 2. 扩展路线

```text
想扩展什么？
    |
    +--> 需要 Python 行为、工具、钩子、后台作业或主动模块
    |       -> Plugin
    |
    +--> 已有独立服务，希望把外部工具接入 Agent
    |       -> MCP
    |
    +--> 主要提供知识、流程、提示词和参考资源
            -> Skill
```

| 路径 | 适合场景 | 是否需要 Python | 主要产物 |
| --- | --- | --- | --- |
| Plugin | 改变运行时行为、注册工具、监听事件、增加后台作业或主动模块 | 是 | `plugin.py`、可选 `plugin.json` |
| MCP | 接入独立进程或外部服务提供的工具 | MCP Server 可使用任意技术栈 | MCP 配置和 Server |
| Skill | 提供领域知识、操作流程、提示词和辅助资料 | 否，可选脚本 | `SKILL.md`、可选 `scripts/`、`references/`、`assets/` |

三条路径都必须经过配置校验、工具守卫、生命周期管理和运行时快照；扩展不能直接修改会话私有状态、绕过权限或在模块导入时创建外部连接。

## 3. Plugin 章节

Plugin 章节解释一个插件如何从目录进入运行时：

```text
plugin.json / plugin.py
          |
          v
插件发现与候选加载
          |
          v
校验、构造上下文、准备贡献
          |
          +--> Tool Registry：动态工具
          +--> EventBus：事件订阅
          +--> Turn Hooks：回合前后处理
          +--> Tool Hooks：调用前参数/权限处理
          +--> Automation：后台作业
          +--> Proactive：主动模块或数据源
          +--> MCP：插件声明的 MCP Server
          |
          v
原子发布运行时快照
          |
          v
热重载、失败回滚、停止清理
```

章节内容：

- 最小插件目录结构；
- `Plugin` 基类和装饰器的使用方式；
- 工具、事件监听、回合钩子、工具钩子、后台作业和主动模块示例；
- 插件配置、数据目录和生命周期；
- 热重载时的新旧版本快照切换；
- 加载失败时保留旧版本的语义；
- 不允许直接操作全局运行时、用户会话和平台 SDK。

## 4. MCP 章节

MCP 章节解释外部能力如何挂载为 Agent 工具：

```text
MCP Server 配置
      |
      v
配置解析与路径校验
      |
      v
MCP Registry
      |
      v
连接、握手和工具发现
      |
      +--> 成功：包装为内部 Tool
      +--> 失败：记录错误，不暴露不可用工具
      |
      v
Tool Registry
      |
      v
工具守卫 -> Agent 调用
```

章节内容：

- 项目级 MCP 配置结构；
- stdio/外部进程 MCP Server 的接入方式；
- `name`、启动命令、参数、环境变量、工作目录和 `watchPaths`；
- 工具发现、包装、注册和调用；
- 连接失败、工具超时、进程退出和配置热更新；
- 插件声明 MCP 与直接项目配置的区别；
- 命名冲突、路径越界、环境变量和密钥安全边界；
- 最小自定义 MCP Server 接入和工具注册验证示例。

文档明确 MCP 是外部工具接入协议，不是直接修改 Agent 主流程的插件机制。

## 5. Skill 章节

Skill 章节解释如何通过知识、流程和资源扩展 Agent，而不直接修改运行时代码：

```text
SKILL.md + skill.json
          |
          v
Skill Loader
          |
          v
Manifest 校验与目录隔离
          |
          v
Skill Registry
          |
          v
按名称/描述匹配当前任务
          |
          v
注入 Prompt 上下文
          |
          +--> scripts：可选辅助脚本
          +--> references：按需参考资料
          +--> assets：模板和静态资源
```

章节内容：

- 最小 Skill 目录结构；
- `SKILL.md` 的职责和推荐写法；
- `skill.json` 的元数据和匹配字段；
- 触发条件、输入约束、步骤、失败处理和输出格式；
- `scripts/`、`references/`、`assets/` 的边界；
- Skill 与 Plugin/MCP 的选择区别；
- 防止 Skill 伪装权限控制、绕过工具守卫或注入不可信指令；
- 领域知识 Skill 和流程型 Skill 的最小示例；
- 加载、匹配、热更新和验证方法。

## 6. 统一生命周期、安全和验证

三条路径共享以下生命周期：

```text
发现
  -> 校验
  -> 准备候选
  -> 原子发布
  -> 运行中使用快照
  -> 热更新替换
  -> 失败保留旧版本
  -> 停止时释放资源
```

文档统一说明：

- 扩展加载失败不能拖垮基础服务；
- 热更新必须先准备新版本，成功后再替换旧版本；
- 正在执行的回合继续使用开始时的扩展快照；
- 外部连接、子进程、线程和事件订阅必须在停止时释放；
- 工具必须经过注册表和守卫；
- 配置、路径、环境变量和密钥在边界处校验；
- 日志不能泄露凭据和个人数据。

验证部分分别覆盖 Plugin、MCP、Skill 的加载、失败、热更新、资源清理和工具可见性，并给出统一启动、测试、日志和运行时状态检查方法。

## 7. 导航

正式文档固定为 `docs/api.md`，并从以下入口直接链接：

- 根目录 `README.md`；
- `backend/README.md`；
- `docs/README.md`；
- `docs/ARCHITECTURE.md` 的扩展层阅读指引。

## 8. 验收标准

- 开发者可以只阅读 `docs/api.md` 选择并完成 Plugin、MCP 或 Skill 的最小接入；
- 每条路径都有目录/配置/运行流程/生命周期/安全边界/验证说明；
- 文档内容与当前 Plugin、MCP、Skill 实现和配置格式一致；
- 文档不把源码路径列表当作主要内容，但可以使用稳定 API 名称和最小代码示例；
- 四个入口均能跳转到 `docs/api.md`；
- 文档不包含未完成占位符、真实密钥或个人数据。
