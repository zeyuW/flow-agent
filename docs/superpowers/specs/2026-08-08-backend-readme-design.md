# Backend README 设计说明

## 目标

为 `backend/` 提供一份面向开发者的入口文档，说明后端当前的代码边界、运行方式、质量检查方式和迁移状态，使新成员能够在仓库根目录之外独立理解并操作后端工程。

## 内容结构

`backend/README.md` 将按以下顺序组织：

1. 项目概览：说明后端用途、Python 版本要求和源码根目录。
2. 目录结构：说明 `src/application`、`src/interfaces`、`src/infra`、`src/bootstrap` 与 `tests` 的职责。
3. 环境安装：提供从仓库根目录安装可编辑后端包的命令。
4. 配置：说明 `config.example.toml`、本地 `config.toml` 和配置加载入口的关系，并提醒不要提交凭据。
5. 运行方式：说明当前服务入口和 CLI/服务启动命令，以仓库内实际入口为准。
6. 验证命令：提供全量测试、格式化检查、类型检查和源码编译检查命令。
7. 开发约束：说明 DDD 分层依赖方向、组合根职责和测试要求。
8. 当前状态：明确旧 `flow_agent` 源码已移除，真实渠道/模型功能仍需在配置凭据和网络条件具备时进行验证。

## 写作约束

- 使用中文，命令可直接复制执行。
- 只记录当前仓库已经存在或可以从配置与代码确认的命令，不编造未实现的入口。
- 区分自动化测试与真实外部服务测试，避免让读者误以为本地测试覆盖真实 Telegram/LLM 环境。
- 保持文档简洁，README 只承担开发入口职责，详细架构继续由 `docs/specs/2026-08-01-ddd-refactor/` 承担。

## 验收标准

- 文档覆盖上述八个主题。
- 文档中的路径、包名和命令与当前 `backend/` 配置一致。
- Markdown 无未完成占位符或互相矛盾的说明。
- 后续可通过现有测试命令验证文档所描述的工程入口。
